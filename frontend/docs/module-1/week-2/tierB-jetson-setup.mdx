## Why This Matters

In edge AI robotics, computational resources are constrained by power, thermal, and physical limitations. NVIDIA Jetson platforms (Nano, Xavier NX, Orin) bridge the gap between laptop simulation and physical robot deployment, offering GPU-accelerated inference while maintaining reasonable power consumption (~5-30W). Understanding Jetson deployment is crucial for robotics engineers who need to optimize algorithms for real hardware constraints.

**Real-World Applications**:
- **Autonomous Drones**: Jetson-powered navigation with real-time object detection
- **Warehouse Robots**: Edge inference for obstacle detection and path planning
- **Agricultural Robotics**: On-board processing for crop monitoring and harvesting

:::danger Hardware Safety
Before powering any Jetson hardware, ensure:
- Use appropriate power supply (official Jetson power adapter recommended)
- Verify correct voltage settings on development carrier board
- Ensure adequate ventilation and thermal management
- Keep emergency stop procedures documented and accessible
:::

## Jetson Setup Process

### Initial Hardware Setup

1. **Unpack and Inspect**: Verify all components (Jetson module, carrier board, power supply, SD card)
2. **Connect Peripherals**: Attach power supply, network cable, keyboard, mouse, monitor (HDMI)
3. **Insert SD Card**: For Jetson Nano, insert the microSD card with pre-flashed OS
4. **Power On**: Connect power supply and press power button (if available)

### Flashing the Jetson OS

For Jetson Nano with SD-CARD model, NVIDIA provides pre-built SD card images:

```bash
# 1. Download JetPack SDK Manager from NVIDIA Developer website
# 2. Install SDK Manager on your host computer (Linux/Windows/Mac)
# 3. Connect Jetson to host via USB
# 4. Put Jetson in recovery mode (hold RECOVERY button, press RESET button)
# 5. SDK Manager will detect Jetson and allow flashing

# Alternative: Flash from command line
sudo ./flash.sh jetson-nano-sd mmcblk0p1
```

### Initial System Configuration

After first boot, configure the Jetson system:

```bash
# 1. Set up user account and password
# 2. Connect to WiFi or Ethernet
# 3. Update system packages
sudo apt update && sudo apt upgrade -y

# 4. Configure power mode (for Nano)
sudo nvpmodel -m 0  # Maximum performance mode
sudo jetson_clocks  # Lock clocks to maximum performance

# 5. Verify GPU access
nvidia-smi
```


### Example: Optimized Image Publisher for Jetson

<CodeExample
  language="python"
  title="jetson_camera_publisher.py"
  tier="B"
  description="ROS 2 publisher optimized for Jetson hardware with reduced resource usage."
>
```python
#!/usr/bin/env python3
"""
Jetson-Optimized Camera Publisher Node

This node is optimized for Jetson hardware constraints:
- Single-threaded execution to reduce overhead
- Image compression to minimize bandwidth
- Reduced frame rate to conserve CPU/GPU
- Proper QoS settings for edge deployment
"""

import rclpy
from rclpy.node import Node
from rclpy.qos import QoSProfile, QoSHistoryPolicy, QoSReliabilityPolicy
from sensor_msgs.msg import Image
from cv_bridge import CvBridge
import cv2
import numpy as np


class JetsonCameraPublisher(Node):
    """Camera publisher optimized for Jetson hardware constraints."""

    def __init__(self):
        super().__init__('jetson_camera_publisher')

        # Create QoS profile optimized for edge computing
        # BEST_EFFORT for high-frequency sensor data to reduce network overhead
        qos_profile = QoSProfile(
            history=QoSHistoryPolicy.KEEP_LAST,
            depth=1,  # Minimal buffering to save memory
            reliability=QoSReliabilityPolicy.BEST_EFFORT,
        )

        # Create publisher with optimized QoS
        self.publisher = self.create_publisher(
            Image,
            '/jetson/camera/image_raw',
            qos_profile
        )

        # Initialize OpenCV bridge for image conversion
        self.bridge = CvBridge()

        # Use timer for controlled frame rate (lower than desktop to conserve resources)
        # 5 FPS instead of 30 FPS to reduce CPU/GPU usage
        self.timer = self.create_timer(0.2, self.publish_camera_image)  # 5 Hz

        # Initialize camera (adjust device index as needed)
        self.cap = cv2.VideoCapture(0)
        if not self.cap.isOpened():
            self.get_logger().error('Could not open camera')
            return

        # Set lower resolution to reduce processing load
        self.cap.set(cv2.CAP_PROP_FRAME_WIDTH, 640)
        self.cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 480)

        self.get_logger().info('Jetson-optimized camera publisher started')

    def publish_camera_image(self):
        """Publish camera image with Jetson-specific optimizations."""
        ret, frame = self.cap.read()
        if not ret:
            self.get_logger().warn('Failed to read from camera')
            return

        # Convert OpenCV image to ROS Image message
        try:
            ros_image = self.bridge.cv2_to_imgmsg(frame, encoding='bgr8')
            ros_image.header.stamp = self.get_clock().now().to_msg()

            # Publish with resource-conscious approach
            self.publisher.publish(ros_image)

        except Exception as e:
            self.get_logger().error(f'Error converting image: {e}')

    def destroy_node(self):
        """Clean up resources when node is destroyed."""
        if self.cap.isOpened():
            self.cap.release()
        super().destroy_node()


def main(args=None):
    rclpy.init(args=args)

    # Use single-threaded executor to minimize overhead on constrained hardware
    node = JetsonCameraPublisher()

    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        node.get_logger().info('Node stopped by user')
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

### Cross-Platform Communication Setup

To communicate between your laptop and Jetson:

```bash
# On both machines, set the same ROS domain
export ROS_DOMAIN_ID=1

# On your laptop, set ROS to find the Jetson
export ROS_IP=<JETSON_IP_ADDRESS>  # Replace with actual Jetson IP
```

## Performance Optimization Strategies

### Memory Management on Jetson

```python
# Example: Memory-efficient image processing on Jetson
import numpy as np
import cv2

def process_image_jetson_optimized(raw_image):
    """
    Memory-efficient image processing for Jetson constraints.
    Avoids creating unnecessary copies of large arrays.
    """
    # Process in-place when possible
    small_image = cv2.resize(raw_image, (320, 240))  # Reduce size early

    # Use numpy operations efficiently
    gray = cv2.cvtColor(small_image, cv2.COLOR_BGR2GRAY)

    # Apply processing with minimal memory overhead
    edges = cv2.Canny(gray, 50, 150)

    return edges
```

### CPU/GPU Load Balancing

```bash
# Monitor and control CPU/GPU usage on Jetson

sudo jetson_clocks  # Lock to maximum clocks (use carefully)

# For thermal management, consider lower power modes
sudo nvpmodel -m 1  # Balanced mode
sudo jetson_clocks --restore  # Restore default clocks
```

## Troubleshooting Common Jetson Issues

### Performance Issues

**Problem**: ROS 2 nodes running slowly on Jetson
**Solution**:
- Check thermal throttling with `sudo tegrastats`
- Reduce node frequency (publish/subscribe rates)
- Optimize image processing (reduce resolution, use efficient algorithms)
- Use single-threaded executors to reduce overhead

### Network Communication Issues

**Problem**: Laptop and Jetson cannot communicate via ROS 2
**Solution**:
- Verify both machines are on same network
- Check ROS_DOMAIN_ID matches on both machines
- Ensure firewall allows ROS 2 traffic (ports 11311 and random high ports)
- Test with `ping <jetson_ip>` from laptop and vice versa

### Resource Constraints

**Problem**: Jetson running out of memory or CPU
**Solution**:
- Monitor with `jtop` to identify bottlenecks
- Reduce image resolution/frame rates
- Use more efficient data types (Float32 instead of Float64)
- Implement proper QoS policies to reduce buffering

## Summary

**Key Takeaways for Jetson Deployment**:

- **Resource Constraints**: Jetson platforms have thermal, power, and compute limitations that require optimized ROS 2 nodes
- **QoS Optimization**: Use BEST_EFFORT for high-frequency data and minimal buffering to conserve resources
- **Performance Monitoring**: Use `tegrastats` and `jtop` to monitor Jetson-specific metrics
- **Cross-Platform Communication**: Configure ROS_DOMAIN_ID and network settings for laptop-Jetson communication
- **Safety First**: Always implement proper thermal management and emergency procedures when deploying to hardware
