# Chapter 12: Simulating Sensors

## Introduction

In robotics, sensors are the eyes and ears of autonomous systems. They provide crucial information about the robot's environment and internal state. In simulation, accurately modeling these sensors is essential for developing robust perception algorithms that can transfer to real robots. This chapter explores how to simulate various sensor types in Gazebo, from basic cameras to complex LIDAR arrays.

## Learning Objectives

By the end of this chapter, you will be able to:
- Configure different sensor types in Gazebo simulation
- Understand the physics behind sensor simulation
- Process sensor data in ROS 2 nodes
- Validate sensor performance in simulated environments

## Real-World Analogy: The Robot's Senses

Think of sensor simulation like creating a virtual human body for a video game character. Just as a game character needs eyes (cameras), ears (microphones), skin (tactile sensors), and a sense of balance (IMU), a robot needs various sensors to perceive its environment. The game engine simulates how light hits the character's eyes, how sound waves reach their ears, and how they feel touch - Gazebo does the same for robots.

## Core Concepts

### 1. Sensor Types in Robotics

Robots typically use several types of sensors:
- **Cameras**: Visual perception for object recognition and navigation
- **LIDAR**: 3D mapping and obstacle detection using laser ranging
- **IMU**: Inertial measurement for orientation and acceleration
- **Force/Torque**: Physical interaction sensing for manipulation
- **GPS**: Global positioning in outdoor environments
- **Encoders**: Joint position and velocity feedback

### 2. Gazebo Sensor Plugins

Gazebo provides sensor plugins that simulate real sensor behavior:
- **libgazebo_ros_camera.so**: RGB camera simulation
- **libgazebo_ros_laser.so**: LIDAR/range sensor simulation
- **libgazebo_ros_imu.so**: IMU sensor simulation
- **libgazebo_ros_f3d.so**: Force/torque sensor simulation

### 3. Sensor Configuration in URDF

Sensors are added to robot models using Gazebo-specific tags in URDF:

```xml
<!-- Example: Adding a camera to a robot -->
<gazebo reference="camera_link">
  <sensor type="camera" name="camera1">
    <update_rate>30.0</update_rate>
    <camera name="head">
      <horizontal_fov>1.3962634</horizontal_fov>
      <image>
        <width>800</width>
        <height>600</height>
        <format>R8G8B8</format>
      </image>
      <clip>
        <near>0.1</near>
        <far>100</far>
      </clip>
    </camera>
    <plugin name="camera_controller" filename="libgazebo_ros_camera.so">
      <frame_name>camera_link</frame_name>
      <min_depth>0.1</min_depth>
      <max_depth>100</max_depth>
    </plugin>
  </sensor>
</gazebo>
```

## Processing Sensor Data in ROS 2

Now let's create a ROS 2 node that processes data from multiple sensors:

```python
#!/usr/bin/env python3

"""
Sensor Data Processing Node
This node subscribes to camera, LIDAR, and IMU data
and demonstrates how to process multi-sensor information.
"""

import rclpy
from rclpy.node import Node
from sensor_msgs.msg import Image, LaserScan, Imu
from cv_bridge import CvBridge
import cv2
import numpy as np


class SensorProcessor(Node):
    def __init__(self):
        super().__init__('sensor_processor')

        # Create subscribers for different sensor types
        self.camera_sub = self.create_subscription(
            Image,
            'camera/image_raw',
            self.camera_callback,
            10
        )

        self.lidar_sub = self.create_subscription(
            LaserScan,
            'scan',
            self.lidar_callback,
            10
        )

        self.imu_sub = self.create_subscription(
            Imu,
            'imu/data',
            self.imu_callback,
            10
        )

        # CV Bridge for image processing
        self.bridge = CvBridge()

        # Statistics for sensor data
        self.camera_count = 0
        self.lidar_count = 0
        self.imu_count = 0

        self.get_logger().info('Sensor Processor Node Started')

    def camera_callback(self, msg):
        """Process camera data"""
        self.camera_count += 1

        try:
            # Convert ROS Image message to OpenCV image
            cv_image = self.bridge.imgmsg_to_cv2(msg, "bgr8")

            # Simple image processing - detect edges
            gray = cv2.cvtColor(cv_image, cv2.COLOR_BGR2GRAY)
            edges = cv2.Canny(gray, 50, 150)

            # Display image with edges overlay
            result = cv2.addWeighted(cv_image, 0.7, cv2.cvtColor(edges, cv2.COLOR_GRAY2BGR), 0.3, 0)

            # Show image (in simulation, this would be headless)
            # cv2.imshow('Camera Feed with Edges', result)
            # cv2.waitKey(1)

            # Log every 30 frames
            if self.camera_count % 30 == 0:
                self.get_logger().info(f'Processed {self.camera_count} camera frames')

        except Exception as e:
            self.get_logger().error(f'Error processing camera image: {e}')

    def lidar_callback(self, msg):
        """Process LIDAR data"""
        self.lidar_count += 1

        # Analyze LIDAR data
        ranges = np.array(msg.ranges)

        # Filter out invalid ranges (inf, nan)
        valid_ranges = ranges[np.isfinite(ranges)]

        if len(valid_ranges) > 0:
            min_distance = np.min(valid_ranges)
            max_distance = np.max(valid_ranges)

            # Calculate number of obstacles within 1 meter
            obstacles = np.sum(valid_ranges < 1.0)

            if self.lidar_count % 10 == 0:  # Log every 10 readings
                self.get_logger().info(
                    f'LIDAR - Min: {min_distance:.2f}m, '
                    f'Max: {max_distance:.2f}m, '
                    f'Obstacles < 1m: {obstacles}'
                )

    def imu_callback(self, msg):
        """Process IMU data"""
        self.imu_count += 1

        # Extract orientation and angular velocity
        orientation = msg.orientation
        angular_velocity = msg.angular_velocity
        linear_acceleration = msg.linear_acceleration

        # Calculate roll, pitch, yaw from quaternion
        quat = [orientation.x, orientation.y, orientation.z, orientation.w]
        roll, pitch, yaw = self.quaternion_to_euler(quat)

        if self.imu_count % 100 == 0:  # Log every 100 readings
            self.get_logger().info(
                f'IMU - Roll: {roll:.2f}, Pitch: {pitch:.2f}, Yaw: {yaw:.2f}'
            )

    def quaternion_to_euler(self, quat):
        """Convert quaternion to Euler angles (roll, pitch, yaw)"""
        x, y, z, w = quat

        # Roll (x-axis rotation)
        sinr_cosp = 2 * (w * x + y * z)
        cosr_cosp = 1 - 2 * (x * x + y * y)
        roll = np.arctan2(sinr_cosp, cosr_cosp)

        # Pitch (y-axis rotation)
        sinp = 2 * (w * y - z * x)
        if abs(sinp) >= 1:
            pitch = np.copysign(np.pi / 2, sinp)  # Use 90 degrees if out of range
        else:
            pitch = np.arcsin(sinp)

        # Yaw (z-axis rotation)
        siny_cosp = 2 * (w * z + x * y)
        cosy_cosp = 1 - 2 * (y * y + z * z)
        yaw = np.arctan2(siny_cosp, cosy_cosp)

        return roll, pitch, yaw


def main(args=None):
    rclpy.init(args=args)

    sensor_processor = SensorProcessor()

    try:
        rclpy.spin(sensor_processor)
    except KeyboardInterrupt:
        pass
    finally:
        sensor_processor.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

## Launch File for Multi-Sensor Simulation

Create a launch file to start the robot with all sensors:

```python
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, IncludeLaunchDescription
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import LaunchConfiguration, PathJoinSubstitution
from launch_ros.actions import Node
from launch_ros.substitutions import FindPackageShare


def generate_launch_description():
    # Launch configuration
    use_sim_time = LaunchConfiguration('use_sim_time', default='true')

    # Robot state publisher node
    robot_state_publisher = Node(
        package='robot_state_publisher',
        executable='robot_state_publisher',
        name='robot_state_publisher',
        output='screen',
        parameters=[{
            'use_sim_time': use_sim_time,
            'publish_frequency': 50.0
        }],
        arguments=[PathJoinSubstitution([
            FindPackageShare('your_robot_description'),
            'urdf',
            'sensor_robot.urdf'
        ])]
    )

    # Joint state publisher (for static joints)
    joint_state_publisher = Node(
        package='joint_state_publisher',
        executable='joint_state_publisher',
        name='joint_state_publisher',
        parameters=[{
            'use_sim_time': use_sim_time
        }]
    )

    # Sensor processor node
    sensor_processor = Node(
        package='your_robot_perception',
        executable='sensor_processor',
        name='sensor_processor',
        output='screen',
        parameters=[{
            'use_sim_time': use_sim_time
        }]
    )

    # Gazebo launch
    gazebo = IncludeLaunchDescription(
        PythonLaunchDescriptionSource([
            PathJoinSubstitution([
                FindPackageShare('gazebo_ros'),
                'launch',
                'gazebo.launch.py'
            ])
        ]),
        launch_arguments={
            'verbose': 'false',
            'pause': 'false'
        }.items()
    )

    # Spawn robot in Gazebo
    spawn_entity = Node(
        package='gazebo_ros',
        executable='spawn_entity.py',
        arguments=[
            '-topic', 'robot_description',
            '-entity', 'sensor_robot',
            '-x', '0', '-y', '0', '-z', '0.5'
        ],
        output='screen'
    )

    return LaunchDescription([
        DeclareLaunchArgument(
            'use_sim_time',
            default_value='true',
            description='Use simulation (Gazebo) clock if true'
        ),
        gazebo,
        robot_state_publisher,
        joint_state_publisher,
        spawn_entity,
        sensor_processor
    ])
```

## Key Considerations for Sensor Simulation

### 1. Computational Performance
- High-resolution sensors require significant computational resources
- Balance sensor fidelity with simulation performance
- Consider using multi-threading for sensor processing

### 2. Noise Modeling
- Real sensors have inherent noise and inaccuracies
- Model sensor noise in simulation for realistic testing
- Use Gaussian noise models for most sensors

### 3. Synchronization
- Multiple sensors may have different update rates
- Implement proper timestamp synchronization
- Consider sensor fusion techniques for combined perception
